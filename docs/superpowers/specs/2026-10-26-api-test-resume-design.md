# API 测试与断点续传设计

## 目标

在不增加主面板负担的情况下，先验证阿里云百炼接口配置，并在长说明书翻译中途遇到 API 故障时保留已完成内容。用户可以换 API Key、地域或自定义接口后继续。

## 交互

- “高级设置”内增加“测试连接”。它用当前 HTTPS 地址、模型和 Key 发送一条很短的 Chat Completions 请求；不包含说明书文字。提示这会产生少量 Token 用量。成功仅报告“连接成功”，不改变文档或翻译任务。
- 测试失败按 HTTP 状态给出可操作提示：401/403 检查 Key、权限与地域；404 检查接口地址与模型；429 检查限流或额度；网络及 5xx 稍后重试。错误不展示 Key。
- 翻译时每批完成后保存该批译文，面板显示“已完成 X/Y 条”。失败后保留成功批次、当前设置和任务；用户修改 Key 或接口后再点“继续翻译”，仅发送尚未完成的条目。主动重新翻译时，旧机器译文保留到对应新批次成功后才替换；待重译清单随任务保存。
- 短暂网络问题、429 和 5xx 继续采用最多三次尝试；认证失败不反复请求。所有 API 都不可用时，保持任务等待用户修复配置，不尝试离线生成。
- 用户主动从校对步骤选择“修改设置并重新翻译”时，可重译尚未手工改写的译文；已手工改写的译文保持不变。

## 技术边界

- 扩展现有翻译函数，增加每批成功回调；面板在回调中写入现有本地任务快照。API Key 仍只保存在面板内存，不写入快照、日志或安装包。
- 连接测试和正式翻译复用 HTTPS 传输层；连接测试检查真实模型响应，不仅做网络探测。
- 继续保持“读取 → 翻译 → 校对 → 应用 → 保存”的单页布局，测试按钮只在“高级设置”中。
- 不自动切换到另一供应商，也不改变 AI 文件回写逻辑。
